# Настройка NTP-сервера

По умолчанию ntpd-rs действует только как NTP-клиент и не предоставляет время ни на один
сетевой интерфейс. Чтобы включить ntpd-rs как сервер, можно добавить следующее в
конфигурацию:

```toml
[[server]]
listen = "0.0.0.0:123"
```

Это заставит ntpd-rs прослушивать все сетевые интерфейсы на UDP-порту 123 для
запросов NTP-клиентов. Если вы хотите прослушивать только определенный сетевой
интерфейс, измените `0.0.0.0` на IP-адрес этого интерфейса.

Теперь вы можете настроить другую машину для использования вашего нового сервера, добавив в
ее конфигурацию:

```toml
[[source]]
mode = "server"
address = "<IP-адрес вашего сервера>:123"
```

## Ограничение доступа
Если вы хотите, чтобы только определенные IP-адреса могли получить доступ к серверу, вы можете
настроить список разрешенных клиентов через механизм списка разрешений. Для этого
отредактируйте конфигурацию сервера следующим образом:

```toml
[[server]]
listen = "0.0.0.0:123"
[server.allowlist]
filter = ["<разрешенный ipv4 1>/32", "<разрешенный ipv4 2>/32", "<разрешенный ipv6 1>/128"]
action = "ignore"
```

При такой конфигурации ваш сервер будет отвечать только перечисленным IP-адресам. IP-адреса записываются в нотации CIDR, что означает, что вы можете
разрешить целые подсети одновременно, указав размер подсети вместо
32 или 128 после косой черты. Например, `192.168.1.1/24` разрешит любой IP-адрес
вида `192.168.1.*`.

Если вы хотите заблокировать определенные IP-адреса от доступа к серверу, вы можете
настроить список заблокированных клиентов следующим образом:

```toml
[[server]]
listen = "0.0.0.0:123"
[server.denylist]
filter = ["<заблокированный ipv4 1>/32", "<заблокированный ipv4 2>/32", "<заблокированный ipv6 1>/128"]
action = "deny"
```

Список запретов использует ту же нотацию CIDR, что и список разрешений, и также может использоваться
для блокировки подсетей. Соединения с IP-адресов, содержащихся в списке запретов, будут
всегда блокироваться, даже если они также случайно находятся в списке разрешений.

Конфигурации списков разрешений и запретов обе необязательны в ntpd-rs. По
умолчанию, если сервер настроен, он будет принимать трафик откуда угодно. При
настройке обоих списков разрешений и запретов ntpd-rs сначала проверит, находится ли удаленный адрес
в списке запретов. Только если это не так, будет
рассмотрен список разрешений.

Свойства `allowlist.action` и `denylist.action` могут иметь два значения:

- `ignore` молча игнорирует запрос
- `deny` отправляет пакет отказа kiss-o'-death

## Добавление вашего сервера в пул NTP

Если ваш NTP-сервер имеет публичный IP-адрес, вы можете рассмотреть возможность сделать его
доступным как часть [пула NTP](https://www.ntppool.org). Пожалуйста, обратите внимание, что
это может оказать значительное долгосрочное влияние в плане NTP-трафика на этот
конкретный IP-адрес. Пожалуйста, внимательно прочитайте [инструкции по присоединению](https://www.ntppool.org/en/join.html)
перед присоединением к пулу.
