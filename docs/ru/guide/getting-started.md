# Начало работы

Ntpd-rs - это реализация протокола NTP. Он направлен на синхронизацию системных часов с временем, полученным из интернета. Он также может, при [настройке в качестве сервера](server-setup.md), предоставлять время другим машинам в сети.

## Установка

Инструкции по установке для вашей системы можно найти в [руководстве по установке](installation.md). Для новых пользователей мы настоятельно рекомендуем использовать либо пакеты из репозитория вашей ОС, либо пакеты, которые мы предоставляем. Если вы установили ntpd-rs из исходного кода и установили файлы в другие места, чем по умолчанию, вам может потребоваться изменить инструкции ниже.

## Проверка синхронизации.

Конфигурация по умолчанию для ntpd-rs настраивает его на синхронизацию с четырьмя серверами, выбранными из [пула NTP](https://www.ntppool.org). Мы можем проверить его статус синхронизации с помощью:

```sh
ntp-ctl status
```

Если все установлено и работает правильно, это покажет информацию, выглядящую как:

```

Desired poll interval: 16s
Stratum: 3

Sources:
ntpd-rs.pool.ntp.org:123/20.101.57.9:123 (1): -0.022944±0.000218(±0.004720)s
    poll interval: 16s, missing polls: 0
    root dispersion: 0.103531s, root delay:0.001434s
ntpd-rs.pool.ntp.org:123/35.204.193.221:123 (2): +0.000564±0.000138(±0.007323)s
    poll interval: 16s, missing polls: 0
    root dispersion: 0.000000s, root delay:0.007538s
ntpd-rs.pool.ntp.org:123/94.198.159.15:123 (3): +0.000140±0.000202(±0.005725)s
    poll interval: 16s, missing polls: 0
    root dispersion: 0.000015s, root delay:0.000015s
ntpd-rs.pool.ntp.org:123/95.211.123.72:123 (4): +0.000052±0.000189(±0.005118)s
    poll interval: 16s, missing polls: 0
    root dispersion: 0.039536s, root delay:0.021667s

Servers:

```

Первый раздел дает общую информацию о синхронизации времени. Дисперсия - это мера того, насколько точно, по мнению системы, определено местное время, а задержка - это мера того, как долго длится коммуникационная задержка до лучшего (наиболее точного) сервера. Желаемый интервал опроса указывает, как часто в настоящее время система хочет узнать время от серверов нижнего уровня, а стратум указывает, сколько серверов находится между нами и эталонным источником времени, таким как атомные часы или GPS-приемник. Стратум всегда будет не менее 2 при настройке в качестве клиента, использующего только источники из интернета.

Далее мы получаем информацию о каждом из источников времени, показывая измеренное отклонение и неопределенность этого значения, а также (в скобках) задержку до сервера. Мы также показываем интервал опроса, используемый для конкретного источника. Это может отличаться от желаемого интервала опроса, если сервер просит нас выполнять меньше запросов. Наконец, отсутствующие опросы дают представление о том, сколько раз мы пытались опросить сервер с тех пор, как последний раз получили измерение времени от него.

Последний раздел пуст, но если бы мы запускали сервер, он бы показывал статистику о том, как часто сервер используется.

## Настройка пользовательского источника времени

Источники, которые ntpd-rs использует для получения текущего времени, можно настроить в файле конфигурации `/etc/ntpd-rs/ntp.toml`. Допустим, что в дополнение к источникам из пула NTP мы также всегда хотим использовать два источника из пула [time.nl](https://time.nl). Для этого мы добавляем следующие строки в файл конфигурации:

```toml
[[source]]
mode = "pool"
address = "ntp.time.nl"
count = 2
```

После перезапуска демона (с использованием `sudo systemctl restart ntpd-rs`, если вы используете Linux) и ожидания некоторого времени для синхронизации статус теперь выглядит как

## Куда двигаться дальше

Теперь у вас есть работающий NTP-клиент, вы можете проверить его статус и при желании изменить источники, которые он использует для времени. Есть несколько направлений, в которых можно двигаться дальше.

Если вы хотите большей уверенности в подлинности ваших источников времени, вы можете взглянуть на [использование NTS](nts.md).

Настройка собственного сервера времени объясняется в нашем [руководстве по настройке сервера](server-setup.md).

При эксплуатации ntpd-rs как части более крупной критической системы вы также можете быть заинтересованы в наших [рекомендациях по защите ntpd-rs](security-guidance.md).
