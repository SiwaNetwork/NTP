# Данные проекта и обработка ошибок

## Какие данные использует проект

Проект читает данные из демона `ntpd-rs` через Unix Socket. Вот что приходит:

### 1. Информация о программе (`ProgramData`)
- `version` - версия демона (например, "1.7.0")
- `build_commit` - Git commit hash сборки
- `build_commit_date` - дата коммита
- `uptime_seconds` - сколько секунд работает демон
- `now` - текущее время в формате NTP timestamp

### 2. Состояние системы (`SystemSnapshot`)
- `stratum` - уровень иерархии NTP (1-15, где 16 = не синхронизирован)
- `time_snapshot.root_delay` - текущее смещение времени (offset)
- `time_snapshot.root_dispersion` - дисперсия (погрешность)
- Другие метрики синхронизации

### 3. Источники времени (`ObservableSourceState`)
- `name` - имя источника (например, "time.google.com")
- `address` - адрес источника
- `reachability` - доступность (0-255, где 255 = все опросы успешны)

### 4. Статистика сервера (`ObservableServerState`)
- `address` - адрес, на котором слушает сервер
- `stats.received_packets` - получено пакетов
- `stats.accepted_packets` - принято пакетов
- `stats.denied_packets` - отклонено пакетов
- `stats.rate_limited_packets` - заблокировано rate limiting

## Что происходит, если демон не запущен

### На бэкенде (HTTP сервер)

1. **При попытке подключиться к Unix Socket:**
   - Ошибка: `UnixStream::connect()` не может подключиться
   - Возвращается HTTP статус `503 Service Unavailable`
   - В логах пишется: `"Не удалось подключиться к демону"`

2. **При чтении данных из сокета:**
   - Если сокет существует, но данные не читаются
   - Возвращается HTTP статус `500 Internal Server Error`
   - В логах: `"Ошибка чтения данных из демона"`

### На фронтенде (веб-интерфейс)

1. **При ошибке HTTP запроса:**
   - Показывается красный баннер с ошибкой: `"⚠️ Ошибка подключения: ..."`
   - Интерфейс продолжает работать, но данные не обновляются
   - Показываются последние известные данные (или значения по умолчанию)

2. **Значения по умолчанию:**
   - `stratum = 16` (не синхронизирован)
   - `sources = []` (пустой список)
   - `uptime_seconds = 0.0`
   - График показывает нули

3. **Поведение:**
   - Каждую секунду пытается переподключиться
   - Как только демон запустится, данные начнут обновляться автоматически

## Как проверить, что демон работает

```bash
# Проверка, что демон запущен
systemctl status ntpd-rs

# Проверка, что Unix Socket существует
ls -la /run/ntpd-rs/observe

# Ручная проверка через команду демона
ntpd-ctl status
```

## Типичные проблемы

1. **"Не удалось подключиться к демону"**
   - Демон не запущен: `sudo systemctl start ntpd-rs`
   - Неправильный путь к сокету: проверь `NTPD_OBSERVE_SOCKET`
   - Нет прав доступа: проверь права на `/run/ntpd-rs/observe`

2. **"Ошибка чтения данных из демона"**
   - Демон запущен, но сокет поврежден: перезапусти демон
   - Несовместимая версия: обнови демон или UI сервер

3. **Интерфейс показывает старые данные**
   - Проверь, что HTTP сервер запущен
   - Проверь логи сервера: `RUST_LOG=debug ./ntpd-ui-server`
   - Открой DevTools в браузере и посмотри Network tab
