# NTPv5
Протокол сетевого времени немного эволюционирует с NTPv5. Эта версия
в настоящее время находится в черновом варианте и предназначена быть следующей основной редакцией
протокола. Хотя NTPv5 работает в основном так же, как NTPv4, есть некоторые заметные
различия:

- NTPv5 описывает только протокол на проводах, опуская любые алгоритмические
  детали, которые были в предыдущих версиях (ни одна из основных реализаций NTP
  точно не следует этим деталям, поскольку они известны как
  субоптимальные).
- Поддержка чего-либо, кроме клиентских и серверных режимов, отброшена (ntpd-rs уже
  поддерживает только эти режимы).
- Поля в сообщениях сервера и клиента NTP были определены более четко.
- NTPv5 имеет лучший механизм для обработки обнаружения циклов.
- Несколько других незначительных улучшений и изменений.

Все это вместе взятое, мы считаем, что NTPv5 - значительное улучшение
по сравнению с NTPv4. По этой причине вы уже можете использовать ntpd-rs в качестве NTPv5 клиента или
сервера, но эта функциональность все еще экспериментальна и не включена по
умолчанию.

Версия 5 протокола NTP, однако, несовместима с более ранними
версиями протокола, учитывая, что некоторые поля изменились. Вот почему механизм
обновления введен в NTPv5, который позволяет клиенту начать с
пакета NTPv4 и позволяет серверу обновить клиента до NTPv5. В следующих
разделах описывается, как включить эту экспериментальную поддержку NTPv5 в ntpd-rs при
использовании в качестве клиента и при использовании в качестве сервера.

!!! Warning

    Поскольку NTPv5 в настоящее время все еще является черновиком IETF, версия черновика клиента
    и сервера должны совпадать, иначе NTPv5 не будет работать. Это означает, что если ваш клиент
    поддерживает черновик 4, сервер также должен поддерживать тот же черновик 4. Чтобы узнать больше
    о спецификации черновика NTPv5, вы можете проверить [веб-сайт IETF](https://datatracker.ietf.org/doc/draft-ietf-ntp-ntpv5/).

## NTPv5 в клиентах

Включение NTPv5 в клиентах можно выполнить, обновив конфигурацию `[[source]]` для
конкретного источника, для которого вы хотели бы включить NTPv5, с использованием поля
`ntp-version`. По умолчанию (`ntp-version = 4`) источники общаются только по NTPv4 (но
принимают пакеты NTPv3 в ответ на наши v4-пакеты). Изменение этого значения на
`ntp-version = "auto"` означает, что механизм обновления будет включен и
позволяет этому источнику обновиться до NTPv5, если сервер также поддерживает NTPv5.
Изменение этого значения на `ntp-version = 5` означает, что этот источник будет только
отправлять пакеты NTPv5, он больше не будет поддерживать версию 4 или ниже, поэтому включайте
этот режим, только если вы уверены, что сервер поддерживает NTPv5. Пример конфигурации
показан ниже, включающий механизм автоматического обновления:

```toml
[[source]]
mode = "server"
address = "ntp.example.com"
ntp-version = "auto"
```

## NTPv5 на серверах

Поскольку серверы могут принимать пакеты от нескольких клиентов с возможно разными
поддерживаемыми версиями NTP, вы можете установить диапазон версий, которые поддерживаются в
вашем сервере. По умолчанию это только версии 3 и 4. Чтобы изменить умолчание
и также включить поддержку NTPv5, перейдите к вашей конфигурации `[[server]]` и добавьте
`accept-ntp-versions = [3, 4, 5]`. Вы также можете удалить `3` из этого списка, чтобы
отключить поддержку NTPv3, например. Пример конфигурации показан ниже:

```toml
[[server]]
listen = "0.0.0.0:123"
accept-ntp-versions = [3, 4, 5]
```

Если ваш сервер также поддерживает сетевую защиту времени (NTS), вам также нужно будет
обновить конфигурацию сервера обмена ключами. По умолчанию сервер обмена
ключами принимает только NTPv4. Чтобы изменить это и поддерживать NTPv5, обновите вашу
конфигурацию сервера `[[nts-ke-server]]` и добавьте `accept-ntp-versions = [4, 5]`.
Обратите внимание, что NTPv3 не поддерживается с NTS, поэтому вы не можете настроить его
как принимаемую версию в вашем сервере обмена ключами. Пример конфигурации:

```toml
[[nts-ke-server]]
listen = "[::]:4460"
certificate-chain-path = "/path/to/certificate/chain.pem"
private-key-path = "/path/to/private.key"
accept-ntp-versions = [4, 5]
```
