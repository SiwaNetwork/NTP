# Источники времени GPS / PPS

## Источник времени GPSd
Вместо использования другого NTP-сервера в качестве источника времени также возможно использовать данные времени из [GPSd](https://gpsd.gitlab.io/gpsd/) в качестве источника времени для ntpd-rs.
GPSd может интерпретировать GPS-сигналы от GPS-приемника, из которых можно определить текущее время.

Для предоставления этой информации gpsd пытается открыть сокет по адресу `/run/chrony.XXXX.sock`, где `XXXX` заменяется именем устройства GPS-устройства. При запуске ntpd-rs с ограниченными правами этот сокет не может быть создан ntpd-rs. Поэтому мы должны настроить systemd (или эквивалентный демон запуска) для создания символической ссылки на папку, в которой ntpd-rs может создать сокет. Мы рекомендуем создать ссылку на `/run/ntpd-rs/chrony.XXXX.sock`, что можно сделать с помощью следующего модуля systemd:

```ini
[Unit]
Description=GPSD Socket Shim
Documentation=https://github.com/pendulum-project/ntpd-rs

[Service]
Type=oneshot
ExecStart=/bin/bash -c "ln -s /run/ntpd-rs/chrony.XXXX.sock /run/chrony.XXXX.sock"
```

Затем GPSd можно добавить в качестве источника времени для ntpd-rs, добавив следующее в конфигурацию:

```toml
[[source]]
mode = "sock"
path = "/run/ntpd-rs/chrony.XXXX.sock"
precision = 1e-3
```

Для источников сокета, таких как GPS-устройство из gpsd, ntpd-rs не может оценить неопределенность данных времени. Поэтому вы должны предоставить собственную оценку (соответствующую 1 стандартному отклонению) этого шума через поле `precision`. Для типичных GPS-приемников неопределенность где-то в диапазоне от 1 до 100 мс является разумной.

### Настройка GPSd
Для того чтобы GPSd мог подключиться к ntpd-rs, GPSd должен запускаться после ntpd-rs и после создания сокета-шайбы. Это связано с тем, что ntpd-rs должен создать сокет для GPSd, который может найти сокет только в том случае, если он существует в момент запуска GPSd.

GPSd можно перезапустить вручную с помощью:

```sh
sudo systemctl restart gpsd.socket
```

Systemd можно указать соблюдать такой порядок запуска с помощью ключей [`Wants`, `Before` и `After` в секции `Unit`](https://www.freedesktop.org/software/systemd/man/latest/systemd.unit.html#%5BUnit%5D%20Section%20Options). Рекомендуется изменять файлы модулей для ntpd-rs и gpsd через `systemctl edit` при внесении этих изменений.

Для получения справки по настройке GPSd на Raspberry Pi, см., например, [это руководство](https://n4bfr.com/2020/04/raspberry-pi-with-chrony/2/).

## Импульс в секунду (PPS)
Ntpd-rs также поддерживает использование данных синхронизации PPS через Kernel PPS, на основе [RFC 2783](https://datatracker.ietf.org/doc/html/rfc2783).

Вот пример конфигурации устройства 1 PPS в ntpd-rs:

```toml
[[source]]
mode = "pps"
path = "/dev/pps0"
precision = 1e-7
```

По умолчанию источники PPS рассматриваются как источники 1 PPS, которые отправляют импульс каждую округленную секунду. Например, для устройства 10 PPS источник можно настроить с периодом 0,1 секунды:

```toml
[[source]]
mode = "pps"
path = "/dev/pps0"
precision = 1e-7
period = 0.1
```
